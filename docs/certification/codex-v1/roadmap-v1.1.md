# Codex v1.1 Roadmap Baseline

## Purpose

This roadmap initializes the Codex v1.1 planning baseline after Codex v1.0
certification.

## v1.1 Principles

- Do not retrospectively change certified v1.0 specifications.
- Preserve all v1.0 identifiers, approvals, versions, and audit history.
- Use v1.0 standards as the governance baseline.
- Treat new requirements as v1.1 changes.
- Require architecture review for v1.1 changes.
- Require implementation, testing, evidence, and certification before v1.1
  release.

## v1.1 Priority Themes

1. Machine-readable registries.
2. Automated traceability.
3. Automated compliance evidence.
4. Structured ADR catalog.
5. Component lifecycle registry.
6. Test evidence registry.
7. Documentation metadata normalization.
8. Dependency graph automation.
9. Certification dashboard automation.
10. Runtime hardening and production validation.

## v1.1 Certification Loop

```text
Codex v1.1 -> New Requirements -> Architecture Review -> Implementation -> Testing -> Certification
```

## v1.1 Non-Goals

- Do not rewrite v1.0 architecture without approved impact analysis.
- Do not delete v1.0 historical documentation.
- Do not bypass Human Final Authority.
- Do not bypass governance, security, testing, accessibility, localization,
  rights, publishing, backup, or lifecycle standards.

## Initial v1.1 Recommendations

- Convert inventory, traceability, compliance, and lifecycle documentation
  into structured registries.
- Add CI-generated evidence for standards and modules.
- Expand runtime tests for modules that remain at scaffolding maturity.
- Add ADRs for major architecture decisions already captured in prose.
- Add automated documentation checks for canonical references.
