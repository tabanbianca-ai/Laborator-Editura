# Codex Standards Version Matrix

## Purpose

This matrix records standard versions and approved standards baseline status.
It does not record product release certification.

## Versioning Rule

All Codex standards use Semantic Versioning:

```text
MAJOR.MINOR.PATCH
```

Incompatible changes require a major version and migration plan. Approved
versions must not be overwritten.

## Product Release Certification

Product release certification is separate from standards versioning. The
authoritative product release decision is recorded in
`docs/releases/v1.0/certification-record.md`.

## Change Requirements

Every future standard change must include:

- Justification.
- Impact analysis.
- Compatibility assessment.
- Migration plan.
- Approval.
- Audit record.

## Backward Compatibility Rule

A new or changed standard must not invalidate the approved Codex standards
baseline without an approved major version, compatibility plan, and migration
roadmap.
