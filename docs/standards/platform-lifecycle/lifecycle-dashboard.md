# Platform Lifecycle Dashboard Standard

## Purpose

This document defines the canonical dashboard model for lifecycle visibility.

## Dashboard Views

A lifecycle dashboard should show:

- Active components.
- Beta components.
- Deprecated components.
- Retired components.
- Archived components.
- Component versions.
- Implementation progress.
- Support levels.
- End-of-life dates.
- Compatibility warnings.
- Migration status.
- Open lifecycle risks.

## Dashboard Record

Every dashboard item should include:

- Component ID.
- Component name.
- Component type.
- Owner.
- Lifecycle stage.
- Maturity level.
- Version.
- Support level.
- Status.
- Dependencies.
- Risk level.
- Compatibility state.
- Deprecation state.
- Retirement plan state.
- Last validation date.
- Next review date.

## Dashboard Rules

- The dashboard must not replace authoritative source records.
- Dashboard data must link to source documentation, lifecycle records,
  compatibility assessments, deprecation records, retirement records, and
  audit evidence.
- AI may summarize dashboard status and suggest risks, but must not approve
  lifecycle transitions.
- Runtime dashboard implementation is not authorized by this standard alone.
