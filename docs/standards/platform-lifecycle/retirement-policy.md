# Platform Retirement Policy

## Purpose

This document defines the required checks before a component is retired.

## Retirement Preconditions

Before removal or retirement, Codex must verify:

- Dependencies.
- Usage.
- Migration completion.
- Documentation updates.
- Backup availability.
- Restore ability where relevant.
- Security impact.
- Tenant impact.
- Rights and publication impact where relevant.
- Approvals.
- Audit history.

## Retirement Record

Every retirement must preserve:

- Retirement ID.
- Component ID.
- Deprecation ID where applicable.
- Final supported version.
- Retirement reason.
- Impact analysis.
- Dependency clearance.
- Migration evidence.
- Backup evidence.
- Archival location.
- Approval.
- Retirement date.
- Audit information.

## Retirement Rules

- Components must not be removed during baseline audits.
- Components must not be removed without approved retirement plans.
- Retired components must preserve enough metadata to support audit,
  traceability, historical reconstruction, and legal or compliance review.
- Publications and editorial records must preserve history even when runtime
  components are retired.
- No permanent deletion is allowed where preservation, rights, audit, or
  compliance records are required.
