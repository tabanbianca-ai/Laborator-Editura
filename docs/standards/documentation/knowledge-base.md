# Knowledge Base Standard

## Purpose

This document defines the canonical model for the unified Laborator Editura
knowledge base.

## Knowledge Base Scope

The knowledge base includes:

- Technical documentation.
- Editorial documentation.
- Glossaries.
- FAQs.
- Procedures.
- Best practices.
- Lessons learned.
- Reusable examples.
- Architecture knowledge.
- Operational knowledge.
- AI governance knowledge.

## Knowledge Record

Every knowledge record should preserve:

- Record ID.
- Title.
- Category.
- Owner.
- Source document.
- Related modules.
- Related standards.
- Related requirements.
- Related policies.
- Related ADRs.
- Tags.
- Summary.
- Validity status.
- Review cycle.
- AI indexing classification.
- Audit information.

## Knowledge Categories

Canonical knowledge categories are:

- `TECHNICAL`.
- `EDITORIAL`.
- `ARCHITECTURE`.
- `API`.
- `AI`.
- `OPERATIONS`.
- `SECURITY`.
- `QUALITY`.
- `PUBLISHING`.
- `RIGHTS`.
- `ACCESSIBILITY`.
- `LOCALIZATION`.
- `USER_GUIDE`.
- `ADMINISTRATOR_GUIDE`.
- `BEST_PRACTICE`.
- `LESSON_LEARNED`.

## Knowledge Governance Rules

- Knowledge content must reference the authoritative source document.
- Knowledge summaries must not replace canonical specifications.
- Knowledge records must be searchable and reusable.
- Outdated knowledge must be marked as superseded or archived, not silently
  removed.
- AI-generated summaries must remain advisory until reviewed when they affect
  governed decisions.
