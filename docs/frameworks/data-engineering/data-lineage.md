# Data Lineage

## Purpose

Data Lineage preserves the history of data origin, transformation,
synchronization, import, export, AI usage, validation, approval, and
publication.

## Lineage Requirement

Every important data transformation must preserve:

- Source entity.
- Source id.
- Source version.
- Target entity.
- Target id.
- Target version.
- Transformation type.
- Transformation id.
- Actor or service.
- AI agent where applicable.
- Organization.
- Workflow state.
- Timestamp.
- Validation result.
- Approval reference where required.
- Audit event reference.

## Lineage Flow

Canonical editorial lineage:

```text
Original Work
  -> Project
  -> Manuscript
  -> Document
  -> Segment
  -> Translation
  -> QA Validation
  -> Semantic Fidelity Validation
  -> Review
  -> Approved Publication Version
  -> Export Artifact
  -> Distribution Record
  -> Public Catalog Record
```

Optional lineage branches:

```text
Approved Publication Version
  -> Audiobook
  -> Video
  -> Magazine Flipbook
  -> Media Localization
  -> Commerce Edition
```

## AI Lineage

AI usage must preserve:

- Input data references.
- Data classification.
- Need-to-Know scope.
- Prompt or prompt version when available.
- Model/provider metadata.
- Output data reference.
- Human approval status.
- Audit event.

AI output is evidence or recommendation until accepted by authorized humans
where approval is required.

## Import Lineage

Imported data must preserve:

- Source type.
- Source reference.
- Source location.
- Source version or edition.
- Imported by.
- Imported at.
- Extraction method.
- License status where relevant.
- Validation status.

## Export Lineage

Exported artifacts must preserve:

- Source master record.
- Source master version.
- Export format.
- Generator version.
- Configuration profile.
- Generated by.
- Generated at.
- Validation result.
- Publication approval state.

## Current Baseline

Lineage currently exists partially through:

- JSON Master provenance.
- Audit tables.
- Version history.
- Export artifacts.
- Publishing records.
- Rights provenance records.
- Workflow transitions.
- Backup metadata.
- AI governance records.
- Research sources and citations.

## Current Gaps

- No central Lineage Service exists yet.
- Lineage is distributed across modules.
- AI data lineage is partially metadata-based.
- Integration and event lineage is not yet represented in a unified registry.
- Lineage graph visualization is not implemented.

## Standardization Plan

1. Define a canonical lineage event schema.
2. Map existing audit/version/export/workflow records to lineage events.
3. Link lineage records to Data Catalog entries.
4. Add lineage for AI consultations and generated outputs.
5. Add lineage validation to export and publication readiness.
6. Add lineage search and visualization in a future approved phase.
