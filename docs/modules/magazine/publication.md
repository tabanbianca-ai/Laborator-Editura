# Magazine Publication

## Purpose

Magazine Publication defines how a reviewed and laid-out issue becomes an
official publication through the Publishing Module.

## Target Outputs

Publishing may generate:

- PDF.
- Flipbook.
- HTML.
- EPUB when configured.
- Mobile Edition.

All outputs must be built from the same approved issue source.

## Current Baseline

Current publication support includes:

- Publishing Module documentation and Phase 7 Step 16 behavior.
- Layout Publishing records and preflight.
- Export artifacts.
- Distribution Center format readiness.
- Public Portal catalog items.
- Commerce edition support.
- Magazine Digital Experience issue visibility and flipbook readiness.

## Publication Rules

- Every article in an issue must be approved before issue publication.
- Rights and Provenance must validate issue/article rights.
- The issue layout must be ready.
- Required formats must exist or be generated by Publishing.
- Publication is delegated exclusively to Publishing.
- Withdrawal and archive must preserve history.

## Issue Publication Flow

```text
Magazine Issue
  -> Article Approval Check
  -> Rights Validation
  -> Issue Layout
  -> Publishing Preflight
  -> Official Publication
  -> Distribution
  -> Archive
```

## Current Gaps

- Magazine issue publication is inferred through project/document status.
- No canonical issue-to-publishing handoff record exists.
- Flipbook generation is a placeholder/readiness concept.
- HTML, EPUB, and Mobile Edition generation are not implemented as issue
  outputs.
- Archive behavior is not a first-class Magazine state.

## Preservation Rule

Magazine publication must preserve Phase 7 Step 16 publishing/preflight/
distribution behavior and must not create separate publication ownership.
