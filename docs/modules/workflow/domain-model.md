# Workflow Engine Domain Model

## Purpose

This document defines the conceptual domain model for the Workflow Engine and
Business Process Automation Module.

It is an architecture baseline and does not authorize immediate database,
API, or runtime changes.

## Core Aggregates

### WorkflowDefinition

Represents a process template.

Fields:

- `workflowDefinitionId`.
- `name`.
- `description`.
- `category`.
- `type`.
- `currentVersionId`.
- `status`.
- `active`.
- `createdBy`.
- `createdAt`.
- `updatedBy`.
- `updatedAt`.

Statuses:

- `DRAFT`.
- `ACTIVE`.
- `SUSPENDED`.
- `ARCHIVED`.

### WorkflowVersion

Represents an immutable version of a workflow definition.

Fields:

- `workflowVersionId`.
- `workflowDefinitionId`.
- `version`.
- `initialStateId`.
- `finalStateIds`.
- `states`.
- `transitions`.
- `rules`.
- `taskTemplates`.
- `approvalRules`.
- `notificationRules`.
- `deadlineRules`.
- `automationRules`.
- `createdBy`.
- `createdAt`.
- `approvedBy`.
- `approvedAt`.

Workflow versions cannot be changed after activation.

### WorkflowInstance

Represents one concrete workflow execution.

Fields:

- `workflowInstanceId`.
- `organizationId`.
- `workflowDefinitionId`.
- `workflowVersionId`.
- `scopeType`.
- `scopeId`.
- `projectId`.
- `documentId`.
- `currentStateId`.
- `currentStatus`.
- `startedBy`.
- `startedAt`.
- `completedAt`.
- `blockedReason`.
- `history`.
- `metadata`.

### WorkflowState

Represents a state within a workflow version.

Fields:

- `stateId`.
- `name`.
- `kind`.
- `order`.
- `responsibleRole`.
- `assignmentRule`.
- `entryConditions`.
- `exitConditions`.
- `allowedActions`.
- `taskTemplates`.
- `approvalRules`.
- `sla`.

### WorkflowTransition

Represents allowed movement from one state to another.

Fields:

- `transitionId`.
- `fromStateId`.
- `toStateId`.
- `action`.
- `conditions`.
- `permissionsRequired`.
- `blockingRules`.
- `eventName`.
- `auditAction`.
- `automationRules`.

### WorkflowRule

Represents configurable IF/THEN business logic.

Fields:

- `ruleId`.
- `name`.
- `version`.
- `expression`.
- `inputs`.
- `result`.
- `ownerModule`.
- `status`.
- `createdBy`.
- `approvedBy`.

### WorkflowTask

Represents an actionable activity generated by workflow.

Fields:

- `taskId`.
- `workflowInstanceId`.
- `stateId`.
- `assigneeUserId`.
- `assigneeRole`.
- `assigneeTeamId`.
- `priority`.
- `dueAt`.
- `status`.
- `comments`.
- `createdAt`.
- `completedAt`.

### WorkflowApproval

Represents a human approval requirement.

Fields:

- `approvalId`.
- `workflowInstanceId`.
- `stateId`.
- `approvalType`.
- `requiredApprovers`.
- `grantedApprovals`.
- `rejections`.
- `status`.
- `createdAt`.
- `completedAt`.

Approval types:

- `INDIVIDUAL`.
- `MULTIPLE`.
- `SEQUENTIAL`.
- `PARALLEL`.
- `CONDITIONAL`.
- `VETO`.

### WorkflowAutomation

Represents a configured workflow automation.

Fields:

- `automationId`.
- `workflowVersionId`.
- `trigger`.
- `conditions`.
- `action`.
- `retryPolicy`.
- `idempotencyKeyStrategy`.
- `enabled`.
- `auditAction`.

### WorkflowSlaRule

Represents response, approval, or completion targets.

Fields:

- `slaRuleId`.
- `workflowVersionId`.
- `stateId`.
- `maxResponseTime`.
- `maxApprovalTime`.
- `escalationRule`.
- `notificationRule`.

### WorkflowAuditEvent

Represents immutable process accountability.

Actions include:

- `WORKFLOW_CREATED`.
- `WORKFLOW_VERSIONED`.
- `WORKFLOW_STARTED`.
- `STATE_ENTERED`.
- `STATE_EXITED`.
- `TRANSITION_EXECUTED`.
- `TASK_CREATED`.
- `TASK_ASSIGNED`.
- `TASK_COMPLETED`.
- `APPROVAL_GRANTED`.
- `APPROVAL_REJECTED`.
- `WORKFLOW_COMPLETED`.
- `WORKFLOW_FAILED`.

## Current Baseline Mapping

| Future concept | Current baseline |
| --- | --- |
| `WorkflowDefinition` | Documented in `docs/workflow`; no runtime aggregate |
| `WorkflowVersion` | Documented only |
| `WorkflowInstance` | `WorkflowState` approximates lightweight instance |
| `WorkflowState` | Current document/segment workflow statuses |
| `WorkflowTransition` | Current `WorkflowTransition` runtime record |
| `WorkflowTask` | Scheduling task metadata, not generated by Workflow |
| `WorkflowApproval` | Dispersed module approval logic |
| `WorkflowRule` | Hardcoded service checks and documented target model |
| `WorkflowAutomation` | Scheduling and local module actions, not centralized |
| `WorkflowAuditEvent` | Current workflow audit events and module audits |

## Ownership Rules

- Workflow owns process coordination.
- Domain modules own domain validation and domain state.
- Scheduling owns calendar/reminder primitives until Workflow integrates with
  it through public contracts.
- Notifications owns message delivery when Module 11 is defined.
- AI Orchestration owns AI execution.
- Audit owns immutable accountability.
